> RTK（Rust Token Killer）是一个单文件 Rust 二进制 CLI 代理，在 shell 命令输出进入 AI 上下文之前做过滤与压缩，官方称可削减常见开发命令 60-90% 的输出量；它最适合已经在用 Claude Code、Cursor、Trae 等 AI 编程工具、并且被冗长的构建/测试/日志输出吃掉上下文窗口的开发者。

## 它到底解决什么问题

AI 编程助手在跑 `cargo build`、`pytest`、`git diff`、`docker ps` 这类命令时，会把整段原始输出读进上下文。官方给出的一个示例会话里，上下文窗口已用 86%、逼近自动压缩阈值，其中 CLI 输出与日志占 18%；经 RTK 过滤后这部分降到 5%，整体回落到 73%，重新留出推理空间。

RTK 的做法不是让 AI 少看东西，而是让它只看有用的东西。官方归纳为四种策略：

| 策略 | 作用 |
|------|------|
| 智能过滤 | 去掉注释、空白、样板文字等噪声 |
| 分组聚合 | 按目录聚合文件、按类型聚合错误 |
| 截断 | 保留相关上下文，砍掉冗余部分 |
| 去重 | 重复日志行折叠为计数 |

典型效果（官方示例）：`cargo build` 从 1042 行压到 4 行，`cargo test` 从 1842 行压到只留失败项。

## 核心概念与工作原理

RTK 是一个「薄代理层」，本身不改变你的工作流，只把噪声拿走。它支持 125+ 条命令，覆盖文件操作、Git、GitHub CLI、测试运行器、构建与 lint、包管理器、运行时、AWS 等类别。

对基于 hook 的 AI 工具（如 Claude Code、Cursor、Trae），RTK 会在命令执行前把 Bash 调用重写，例如 `git status` 自动变成 `rtk git status`，AI 拿到的是压缩后的输出，无需显式调用 `rtk`。对基于插件的工具（如 Hermes），则通过插件 API 在命令执行前重写。

> **重要限制**：hook 只作用于 Bash 工具调用。Claude Code 内置的 `Read`、`Grep`、`Glob` 等工具不经过 Bash hook，不会被自动重写。要让这些场景也享受压缩，需要改用 shell 命令（`cat`/`head`/`tail`、`rg`/`grep`、`find`），或直接调用 `rtk read`、`rtk grep`、`rtk find`。

关于「省 token」的口径，官方特意做了澄清：RTK 削减的是 **bash 输出**，这不等于账单降低 90%。bash 输出只是输入 token 的一部分，输入 token 又只是账单的一部分，削减比例会逐层稀释。另外 RTK 不内置 tokenizer，token 数按 `bytes / 4` 估算，**百分比可信，绝对 token 数只是近似值**。

## 在 Windows 上安装

### 方式一：winget（Windows 推荐）

官方称这是 Windows 上最省事的方式，一条命令，无需手动配 PATH：

1. 打开 PowerShell。
2. 执行 `winget install rtk-ai.rtk`。
3. 等待安装完成后，关闭并重新打开终端。

### 方式二：预编译二进制

1. 从 GitHub releases 下载 `rtk-x86_64-pc-windows-msvc.zip`。
2. 解压，把 `rtk.exe` 放到 PATH 中的某个目录，例如 `C:\Users\<你的用户名>\.local\bin`。
3. 从 **命令提示符、PowerShell 或 Windows Terminal** 中运行 RTK。

> **不要双击 `rtk.exe`**：它会一闪而过直接退出。

### 方式三：Cargo

若本机已有 Rust 工具链，用显式 Git 地址安装，避免装成同名项目：`cargo install --git https://github.com/rtk-ai/rtk --branch master rtk`。

### 验证安装

1. 执行 `rtk --version`，应输出形如 `rtk x.y.z` 的版本号。
2. 执行 `rtk gain`，应显示节省面板。

两条都通过即安装成功。若 `rtk gain` 失败，先卸载误装的包再重装。

## 接入 Trae Work 与 Java / Spring 工作流

RTK 官方明确提供了 Trae 的接入路径，这是它对本读者群最直接的价值点。

### 接入 Trae

1. **项目级接入**：在项目根目录执行 `rtk init --agent trae`，会在项目的 `.trae/hooks.json` 写入 hook 配置。
2. **全局接入**：执行 `rtk init -g --agent trae`，作用于 `~/.trae` 以及已存在的 `~/.trae-cn`。
3. 重启 Trae Work，让 hook 生效。
4. 在 Trae Work 的终端里执行 `git status`，若被自动重写为 `rtk git status` 并返回紧凑输出，说明接入成功。

> 官方未提供与 Trae Work 的 MCP 服务接入方式，也未提供 Java / Spring 的 SDK 或 HTTP 集成方式。RTK 的定位是 CLI 代理与 hook，不是库。

### 在 Java / Spring 项目里怎么用

RTK 的命令清单里没有 `mvn` 之外的 Java 专属条目，但提供了 Maven 相关支持：`rtk mvnd verify` 使用与 `rtk mvn` 相同的过滤器。对 Spring 项目常见的 `mvn` / `mvnd` 构建、`gradle` 测试输出，可优先尝试用 `rtk` 前缀包裹命令，或依赖 hook 自动重写。

> 官方命令清单中未列出 Gradle 专属过滤器，暂无公开资料说明其对 Gradle 输出的压缩效果。

### 常用命令速查

| 场景 | 命令 |
|------|------|
| 目录树 | `rtk ls .` |
| 智能读文件 | `rtk read file.java` |
| 只读签名 | `rtk read file.java -l aggressive` |
| 搜索 | `rtk grep "pattern" .` |
| 找文件 | `rtk find "*.java" .` |
| Git 状态 | `rtk git status` |
| Git 日志 | `rtk git log -n 10` |
| Git 差异 | `rtk git diff` |
| 测试（失败项） | `rtk test <cmd> [args...]` |
| 错误与警告 | `rtk err <cmd> [args...]` |
| Maven Daemon | `rtk mvnd verify` |
| 节省面板 | `rtk gain` |

## 快速上手

1. 用 winget 装好 RTK，确认 `rtk --version` 与 `rtk gain` 都正常。
2. 在 Trae Work 打开你的 Spring 项目，于项目根目录执行 `rtk init --agent trae`。
3. 重启 Trae Work。
4. 让 AI 助手跑一次 `git status` 或 `mvn -q compile`，观察返回内容是否明显变短。
5. 执行 `rtk gain` 查看累计节省面板。

## 如何确认运行成功

- `rtk --version` 输出版本号。
- `rtk gain` 显示节省面板。
- Trae Work 中执行 `git status` 被自动重写为 `rtk git status`，输出为紧凑格式。
- 官方称 hook 系统在 Windows 上原生可用，也可在 WSL 中使用。

## 局限与风险

**口径风险**：官方反复强调，削减的是 bash 输出，不是账单。把「省 90%」理解成「省钱 90%」会失望。

**命名冲突**：crates.io 上有同名项目，`cargo install rtk` 有装错风险，务必用 Git 地址或 winget。

**覆盖范围有限**：hook 只作用于 Bash 工具调用，AI 工具内置的 Read / Grep / Glob 不经过 hook，需要手动改用 shell 命令或 `rtk` 子命令。

**Java 生态覆盖偏薄**：命令清单中 Java 相关只有 Maven Daemon 一条，Gradle 暂无公开说明。

**成熟度**：仓库创建于 2026-01-22，最近更新 2026-10-11，属于较新的项目；官网显示 1.6M+ 下载、82.9K+ GitHub stars、140K+ 开发者、125+ 命令、17 个 AI 编程工具集成。

**许可证**：Apache 2.0，可商用。

**安全**：官方仓库带 Security Check CI 徽章；遥测为选择性加入且不含个人数据。

## 一句话结论

如果你在 Windows 上用 Trae Work 写 Java / Spring，且经常被构建、测试、Git 的冗长输出挤爆上下文，RTK 的接入成本极低（一条 winget 命令 + 一条 `rtk init --agent trae`），值得花十分钟试一次；但别指望账单直接砍掉九成，Java 生态的过滤器覆盖也还比较薄。
